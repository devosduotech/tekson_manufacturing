## Overview

v15.1.39 is the release that makes **Daily Material Planning quantity and
target-warehouse behaviour correct and self-explaining**. It closes the four
issues found during the October UAT trial of the Material Planning page and
the Material Transfer Pick List report, and hardens the role gates so floor
roles can actually execute their Job Cards.

Nothing in the planning fixes (v15.1.36–v15.1.39) changes a doctype, but this
release also carries **v15.1.35 role-alignment** (`8b3c943`), which edits the
**permission JSON** of the Pick List report, the BOM Bulk Creator doctype and
the Tekson workspace. Sites upgrading from `v15.1.33` must therefore run
**`bench migrate`** to sync those role permissions.

Deployment is `git pull` + `bench migrate` + `bench build --force` +
`bench restart`.

## What's Included

### Daily Material Planning (v15.1.36 – v15.1.39)

| Version | Fix |
|---------|-----|
| v15.1.36 | MR `qty` = required (incl. RM Loss) − stock already in the target WIP, **aggregated across all of the day's Work Orders**, deducted once. Previously stock was ignored, or deducted once per WO / per source warehouse, so requirements either vanished or were over-requested. `Bin` lookup now uses exact warehouse names instead of `LIKE '%WIP%'` |
| v15.1.37 | The transfer **target warehouse comes from the BOM Item's operation** (`BOM Operation → workstation → plant floor → WIP-{floor} - TPL`), never from the Work Order header warehouse (which ERPNext derives from the BOM's **first** operation). Multi-floor BOMs no longer dump material on the wrong plant floor. Unresolvable items are **skipped with a visible warning** instead of silently mis-targeted; a stale Job Card WIP loses to configuration and warns "re-save the Job Card". The Pick List report got the same rule plus an **Operation** column |
| v15.1.38 | Operation matching is **case- and whitespace-insensitive** across BOM Item, BOM Operation row and Job Card (`normalize_operation`). Casing differences (`Tank Assembly` vs `TANK ASSEMBLY`) no longer break resolution or the Job Card fallback |
| v15.1.39 | Skip warnings **name the broken configuration link**; Job Card `workstation → plant_floor` is used when its `wip_warehouse` is blank; a *unique* `WIP-{floor}` naming variant is accepted when the convention name is missing (ambiguous matches are never guessed) |

### MES Role Gates (v15.1.34 – v15.1.35)

## Why the Target-Warehouse Change Matters

Before v15.1.37 an MR line's destination was:

```python
target_wh = jc_map.get((wo, operation)) or wo.wip_warehouse   # ← first-operation WIP
```

Any Job Card lookup miss (trailing whitespace in the operation key, a split
Job Card with an empty WIP, or Job Cards not created yet) fell back to
`Work Order.wip_warehouse` — the warehouse of the BOM's **first** operation.
On BOMs that span plant floors, material was requested into a department that
would never consume it, while the department that needed it stayed short.

Now the operation's own routing drives the target, and the Work Order header
is used **only** for BOM Items that carry no operation (with a warning).

**Resolution chain** (`utils/operation_warehouse.py`, shared by Material
Planning and the Pick List report):

```
BOM Item.operation
  → BOM Operation row (case/whitespace tolerant; child-BOM routing first)
    → workstation_type (or direct workstation link)
      → first Workstation of that type (name asc)
        → plant_floor
          → WIP-{plant_floor} - TPL  (must exist; unique variant accepted)
  fallback: Job Card.wip_warehouse → Job Card.workstation → plant_floor
  never:    Work Order.wip_warehouse (for items that carry an operation)
```

## Reading the New Warnings

A skipped item now tells you exactly what to fix:

```
Item ALU- STD- 0049 on Work Order WO/261027/0321: warehouse for operation
Tank Assembly could not be resolved (routing row 'Tank Assembly' of BOM
'BOM-TANK-001' has no workstation / workstation type; no Job Card WIP
warehouse for operation Tank Assembly on this Work Order) — material skipped
```

| Reason in the warning | Fix |
|-----------------------|-----|
| `BOM '<bom>' routing has no operation '<op>' (routing: …)` | The BOM Item's operation is not a routing row (or lives in another BOM) — correct the BOM |
| `routing row '<op>' of BOM '<bom>' has no workstation / workstation type` | Set **Workstation Type** (or Workstation) on that routing row and submit the BOM |
| `no Workstation of type '<type>'` | Create a Workstation with that **Workstation Type** |
| `Workstation <ws> has no plant floor` | Set **Plant Floor** on the Workstation |
| `warehouse WIP-<floor> - TPL does not exist for plant floor <floor>` | Create the department WIP warehouse with that exact name |
| `… several WIP warehouses match plant floor <floor>: A, B` | Rename/remove the duplicates — ambiguous targets are never guessed |
| `no Job Card WIP warehouse for operation <op> on this Work Order` | Job Cards are not created yet, or their `wip_warehouse` is blank — re-save them |

Other warnings: **no valid source warehouse** (item skipped), **BOM Item has
no operation** (falls back to the WO WIP), **Job Card WIP disagrees with the
operation's configuration** (configuration wins; re-save the Job Card).

## Deployment

```bash
# UAT (cwd_admin@cwd)
cd ~/cwd-bench/apps/tekson_manufacturing
git pull origin main
cd ~/cwd-bench && bench --site tekson.site migrate && bench build --force && bench clear-cache && bench restart

# Dev (karthic@teksons-development)
cd ~/frappe-bench/apps/tekson_manufacturing
git fetch upstream && git reset --hard upstream/bom-bulk-creator
cd ~/frappe-bench && bench --site teksons.dev migrate && bench build --force && bench clear-cache && bench restart
```

- **`bench migrate` IS required** when upgrading from `v15.1.33`: v15.1.35
  changed the permission JSON of the Pick List report, the BOM Bulk Creator
  doctype and the workspace. `migrate` syncs those role permissions into the
  site (the planning fixes alone would not need it)
- **`bench build --force` is required on UAT**: the desk assets there pre-date
  Frappe commit `2b29354` (2026-09-10), which removed `_comments` from the
  standard list fields. Stale JS still requests it and every list view fails
  with `Field not permitted in query: tabJob Card._comments`. Rebuilding
  assets clears it; then hard-refresh the browser
- Verify after deploy: `bench version` shows `tekson_manufacturing 15.1.39`
