## Critical Fixes in v15.1.5

These fixes were identified during internal testing and are essential for correct MES behavior.

### 1. Department Transfers Trigger JC Refresh
- **File:** `services/stock_service.py`
- **Issue:** `create_department_transfer()` used `stock_entry_type` instead of `purpose`, so the coordinator's `on_stock_entry_submit` check (`purpose == "Material Transfer for Manufacture"`) never matched, and JCs were never refreshed after a transfer.
- **Fix:** Changed to `purpose: "Material Transfer for Manufacture"`.

### 2. `custom_start_status` Synced with Readiness Engine
- **File:** `readiness/job_card_readiness.py`
- **Issue:** `apply_result_to_job_card()` never updated `custom_start_status`, so it stayed stuck at "Awaiting" even when material was available.
- **Fix:** Added `custom_start_status` mapping from `ReadinessStatus` values.

### 3. Removed Broken JS Reference
- **File:** `hooks.py`
- **Issue:** `doctype_list_js` referenced `public/js/job_card_list.js` which didn't exist, causing the Status column to disappear on refresh.
- **Fix:** Removed the broken reference.

### 4. `complete_job_card` Triggers Downstream Refresh
- **File:** `api/job_card_start.py`
- **Issue:** `complete_job_card()` used `jc.save()` which never fired the `on_submit` hook, so downstream JCs were never refreshed.
- **Fix:** Added `refresh_next_job_card()` + WO completion check directly in the API.

### 5. Refresh ALL Parallel JCs
- **File:** `readiness/job_card_readiness.py`
- **Issue:** `refresh_next_job_card()` only refreshed one JC at `sequence_id + 1`, missing parallel operations.
- **Fix:** Now refreshes ALL JCs at the next sequence.

### 6. JC Status Fields Reflect Lifecycle State
- **File:** `utils/job_card_utils.py`
- **Issue:** `custom_can_start_operation` and `custom_material_available_for_operation` were stale after status changes.
- **Fix:** `update_job_card_status()` now sets all 3 fields based on JC state (Open/WIP/Completed).

### 7. `validate_job_card_start` Owns `can_start`
- **File:** `utils/job_card_utils.py`
- **Issue:** Two parallel status systems (`custom_start_status` vs `custom_readiness_status`) were unsynchronized.
- **Fix:** `validate_job_card_start()` is now the single source of truth for `custom_can_start_operation`, based on the live material check.

### 8. WO Status on Manufacture SE
- **File:** `mes/mes_coordinator.py`
- **Issue:** `on_stock_entry_submit` only handled "Material Transfer for Manufacture", so a "Manufacture" SE never updated the WO status.
- **Fix:** Added handling for "Manufacture" purpose → updates WO status to Completed.

### 9. Exploded Multi-Level BOM for Material Requests
- **File:** `planning/material_planning_service.py`
- **Issue:** `_get_raw_bom_items()` only read direct BOM items, missing sub-assembly raw materials (e.g., Helicoil Insert 22 vs 24).
- **Fix:** Added `_explode_bom()` with **memoization** (per-unit caching) to correctly handle repeated sub-assembly references.

### 10. Proper SE Insert + SLE Verification
- **File:** `execution/execution_engine.py`
- **Issue:** `complete_work_order()` used `se.insert(ignore_permissions=True)` which caused the Manufacture SE to submit WITHOUT creating stock ledger entries.
- **Fix:** Removed `ignore_permissions=True` and added SLE count verification.

### 11. Material Readiness Skips Sub-Assemblies
- **File:** `readiness/material_readiness.py`
- **Issue:** `get_required_materials()` included sub-assemblies (manufactured components), causing incorrect material availability flags.
- **Fix:** Sub-assemblies are now skipped — handled by the child WO completion check (dependency engine).

### 12. `refresh_job_card_status` Single Evaluation
- **File:** `api/job_card.py`
- **Issue:** `JobCardService.refresh_status()` evaluated material readiness 3 times.
- **Fix:** Now uses `JobCardReadinessEngine.refresh_job_card()` (single evaluation), consistent with auto-update hooks.

## Known Data Considerations

- BOM `source_warehouse` and `target_fg_warehouse` must be correctly configured by engineering (defines material flow).
- `source_warehouse` in BOM Item = where the material is consumed (reference).
- `target_fg_warehouse` in BOM = where the next operation starts (authoritative).
